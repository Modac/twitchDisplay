# Host simulation

Runs the real firmware code (`src/twitchDisplay.cpp`, `lib/LogoImage`) on the
PC. The Arduino core, display, WiFi, web server, HTTP client, flash, NVS,
FreeRTOS and the ROM inflater are replaced by small stand-ins in `stubs/`
that record what the firmware does (pixels in a 320×170 framebuffer, HTTP
requests, flash writes, NVS keys, …). Twitch, GitHub and the image server are
simulated with scripted HTTP responses.

## Run

```bash
./run.sh
```

It builds and runs three variants of the firmware configuration:

| Variant | `secrets.h` defaults |
|---|---|
| `TOKEN` | WiFi, web password and a fixed Twitch token |
| `SECRET` | WiFi, web password and a Twitch client ID + secret |
| `NOSECRETS` | nothing: the firmware starts in setup mode |

`./run.sh TOKEN` runs one variant. Needs `g++` (C++17), the zlib development
files and the PlatformIO libraries of the main environment (`run.sh` installs
them with `pio pkg install -e twitchDisplay` if they are missing).

## What is tested

- Channel tiles, scrolling title, redraws when channels go live/offline or
  change rows, "+N" tile, status dot
- Twitch requests: token from the client secret and renewal on 401, JSON
  filtering, errors, WiFi loss and reconnect, background task vs. `loop()`
- UTF-8 → display charset conversion, LDR sampling, CRLF serial output
- Web interface: login, status/settings/update pages, HTML escaping,
  firmware upload with file check, online update from GitHub releases,
  rollback protection and firmware confirmation
- Settings in NVS, setup hotspot (first start, WiFi not reachable, BOOT
  button, reset)
- Channel list (names, lookup, cache, unknown names) and logos (download,
  conversion, flash slots, errors keep the old logo, "Reload logos")

Firmware images and avatars are generated by `test_data.h`; no build outputs
or third-party images are needed.

## Optional checks

**Logo quality** (needs Python with numpy and Pillow): converts generated
PNGs (all colour types and row filters, transparency, broken files) with
`pngToLogo` and compares them with an exact area-average reference.

```bash
python3 logo_quality.py
```

**Online update page in a browser** (needs Node.js and Playwright): drives
the "Online update" card of the generated Update page against a mock of the
firmware's endpoints.

```bash
DUMP=1 ./run.sh TOKEN
```

```bash
node web_test.js
```

`DUMP=1` also writes the generated status, settings and update pages as
`*.html` files, which can be opened in a browser.
